# Objective

Astatka window (`/astatka/<O-flight>`), partner cargo. When a scanned track code is not in our database, the backend now asks a partner cargo's read-only API (first partner: **AKB**). A hit comes back as an ordinary `kind: "new"` proposal whose package carries `source_company: "AKB"` and the partner's data for that bag. The window must:

1. mark every such bag with a clear "AKB · API" chip (work rows, last-scan banner, bag window, saved list);
2. show the partner's data in the bag window instead of our photo report (which would show an unrelated client of ours with the same code), with the partner's photos when its API sends links, and let the worker pick which of the client's partner flights the bag is when there are several;
3. send `source_company` on "Tasdiqlash" so the backend saves the bag only into the astatka's own records;
4. offer "Qayta tekshirish" on a row the server could not find (e.g. the partner API was down);
5. filter the saved list by cargo ("Hammasi" / "Mandarin" / "AKB") when the astatka holds partner bags.

Our own cargo keeps `source_company: ""` and behaves exactly as before.

# Walkthrough / Architecture

The backend answers a scan of a code it does not know with the partner's view of that client: the bag it believes the code is in (`package`, with `source_company`, `source_company_name`, `external`) plus every flight the partner holds for the client (`external_options`, newest first) and whether the code's flight was known or assumed (`external_flight_known`).

`applyScanResult` stores the options on the work row (`externalOptions`, `externalFlightKnown`); a later answer without options (an offline answer, a re-scan of a saved bag) keeps them as long as the bag is still that partner's. The worker picks a flight in the bag window's `ExternalBagCard`, which writes it through the hook's existing `updateEdits(row.id, { ...edits, sourceFlight })`. `rowView` reads the picked option back (weight, rows, photo count, partner data) so the row, the banner and the summary all show the chosen bag; a weight the worker typed still wins. "Tasdiqlash" sends `source_company` and the chosen flight; the server re-reads the partner's data itself, so only a typed weight goes with it.

`lib/astatkaSource.ts` is the single answer to "is this a partner's bag and what is it called" (missing fields count as our cargo). Every surface that would otherwise read our photo report (`BagPhotoReport`, `getAstatkaBagDetails`) checks it first: a partner bag's `bagRefOf` is `null` and `BagSheet` renders `ExternalBagCard` in its place. Partner photos are links the partner's API sends (`photo_urls`, short-lived); when there are none, only the count is shown, because the partner's Telegram file ids cannot be opened here.

The saved list adds a cargo filter only when the server reports partner codes in this astatka (`source_companies`). The chosen value goes out as `source_company` (`""` = ours), and the offline copy filters the same way.
